# Seedance 服务器视频流水线

> 2026-11-27：`text_overlay_render.py` 为已停止的手工排版实验，未接入活动服务、未用于已验收成片，不应作为最新“仅云端提示词编辑”流程运行。当前状态见 [进度交接](../docs/progress/2026-11-27-cloud-only-handoff.md)。

`media_service.py` 与 `media_processing.py` 提供私有 MP4 暂存及机械处理任务。原片只上传一次，服务器按每段不超过 15 秒切分；桌面插件调用 Seedance 编辑各段后，把临时结果地址交给服务器下载。服务器拼接云端候选并复用原声音轨，桌面最后只下载完整候选。

服务不接收 Ark API Key，也不调用模型；视频理解、翻译和画面编辑仍全部由 Seedance 完成。服务器只执行 FFmpeg 技术操作和文件传输。这些服务器组件不装入桌面插件；部署需要独立 Linux 服务账号、持久数据目录、FFmpeg/FFprobe 及既有 HTTPS 反向代理。

## 接口与传输

服务默认仅监听 `127.0.0.1:8791`，由 HTTPS 代理转发 `/codex-media/`。健康检查为 `GET /codex-media/healthz`。对象路径为 `/codex-media/v1/objects/{sha256}`，对象 ID 是完整文件的 SHA-256。

- 认证 GET 查询完整对象；`GET .../upload` 查询当前接收偏移。
- `PUT .../upload?offset=N&total=M` 上传最多 256 KiB 的完整块，使用 `application/octet-stream` 和精确 Content-Length。插件从服务端报告的偏移续传；已完成对象先通过哈希查询复用。
- 完整 MP4 通过文件头与 SHA-256 检查后才发布。未完成或损坏的片段不能取得下载签名。
- `POST .../ticket` 为一个对象签发只读链接。签名默认 6 小时、最长 12 小时，GET、HEAD 和单段 Range 都必须验签。

所有控制接口使用独立上传令牌。它和 Ark API Key 应分别保存于插件的 Windows 凭据管理器中；服务端配置只包含上传令牌与签名密钥。配置文件、SSH 凭据和签名 URL 不应加入源码、安装包或访问日志。

## 持久处理任务

`POST /codex-media/v1/jobs` 接收最多 64 KiB 的 JSON，需要独立上传认证，提交后返回任务 ID 和状态；`GET /codex-media/v1/jobs/{id}` 查询同一任务。接口拒绝多余字段、重复 JSON 键、非 JSON、流式未知长度正文及查询参数。

支持三类请求：

```json
{"kind":"split","source_id":"<原片SHA256>","policy":"fixed-15s-v1"}
{"kind":"import","task_id":"cgt-...","url":"<Seedance临时HTTPS结果地址>"}
{"kind":"join","source_id":"<原片SHA256>","split_job_id":"<分段任务ID>","parts":[{"index":1,"task_id":"cgt-...","object_id":"<候选SHA256>"}]}
```

任务 ID 由请求的稳定字段决定；结果导入只按模型任务 ID 绑定，临时 URL 只在内存中使用，不写入任务状态或日志。任务状态为 `queued`、`running`、`succeeded` 或 `failed`。同一请求重复提交可复用已经完成的结果；服务中断的任务可以按同一 ID 恢复，桌面不会因此重新提交 Seedance 生成。

分段接受 4–300 秒、24–60 fps 的恒定帧率视频，最多 20 段。每段不超过 15 秒；若末段不足 4 秒，从前一段借帧，使最后两段都满足模型限制，不丢帧、不重复。43.4 秒视频按 15 + 15 + 13.4 秒切分。切片保持原画幅和帧率，重新编码为 H.264；片段音频仅作输入上下文，最后使用原片音轨。

结果导入只接受公共 HTTPS 地址，拒绝私网、链路本地地址、重定向及 URL 内凭据；解析 DNS 后固定已校验的地址，保留 TLS 主机验证，不携带任何 Authorization。服务器校验文件大小、媒体格式与 SHA-256 后才发布对象。

拼接必须使用与原片、分段任务和顺序绑定的完整候选清单。服务器检查编码兼容性后复制视频流拼接，复制原声音轨并核验音频包和起始偏移；不会裁帧、补帧或改变速度来掩盖云端输出偏差。兼容候选可以保留完整输出，但时长、帧率或画幅差异会使技术报告失败。技术通过不代表文字、遮挡、切镜或译文已通过视觉验收。

## 保留与故障恢复

完整对象和未完成分块在 3 天闲置后过期，过期数据在后续上传时清理；服务没有后台定时删除器。认证签发新的读取链接会续期对应完整对象的保留时间。默认目录配额为 10 GiB，写入时至少保留 2 GiB 磁盘空间，并发请求上限为 8。

服务 `1.1.3` 修复过期完整文件的恢复路径：完整对象查询返回 `410` 后，同一哈希可分块重新上传，不再被未清理的旧文件永久阻塞为 `409 already_complete`。仍有效的完整文件不会被分块覆盖。已接收全部字节但尚未发布的分块文件可以用匹配末尾偏移的空块完成哈希校验及发布。

服务 `1.2.0` 增加上述任务接口。单个处理 worker 限制并行媒体计算，提交队列有界；任务状态持久化，临时计算目录和对象受磁盘配额、保留期限及空闲空间检查限制。取消桌面等待不会删除已上传对象，也不会自动取消已提交的云端生成。

上传后响应丢失时，应先查询对象与上传偏移，不能直接假定上传失败。上传不创建模型任务；创建生成任务仍由桌面插件单独保存提交状态与任务 ID。版权等平台策略拒绝应保留原始失败类别，不自动重新生成或修改内容规避拒绝。

## 部署与更新

使用 `python media_service.py --help` 查看服务参数。上传令牌和签名密钥应为分别生成的随机值，配置文件只允许专用服务账号读取。反向代理需要保留签名查询参数，支持 HEAD 和 Range，关闭该路径的访问日志并限制请求体大小；不要修改业务站点的认证规则。

将两个 Python 文件作为同一版本部署，记录各自 SHA-256，通过服务管理器切换整个版本目录。升级到 `1.2.0` 需要更新并重启服务器侧服务；桌面重装不会更新服务器。升级时保留原数据目录、上传令牌与签名密钥，使现有对象及尚未过期的链接继续有效。此前部署器包含用户专用配置，未纳入此通用源码目录。

`GET /codex-media/healthz` 返回版本、处理能力及 FFmpeg/FFprobe 就绪状态，不返回二进制路径或秘密。处理服务应使用适当的 systemd 内存、任务数和 CPU 限额；仅有上传功能时的 256 MiB 限额不足以保证 1080p/60 编码。生产部署采用单 worker、FFmpeg 线程上限及专用数据目录，避免占用其他网站的运行资源。配置可选 `ffmpeg`、`ffprobe` 指定已安装程序，否则使用服务 PATH。

桌面插件会把上传后端与处理方式绑定到批次；改变服务器后需要新批次，不能把旧 Ark Files 或本地分段断点混入新服务器流程。回归使用合成媒体及回环 HTTP，见 `tests/test_selfhost_media.py`、`tests/test_media_service.py`、`tests/test_media_jobs_http.py` 和 `tests/test_server_processing.py`，不需要真实模型调用或真实凭据。

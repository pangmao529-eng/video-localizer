# Video Localizer · 视频改字与模型 API 配置

本分支为 **0.2.0rc15 候选版**。支持 Seedance 2.0 分段云端编辑与 2.5 整片云端编辑：上传素材、创建编辑任务、查询进度、下载候选成片、保留断点及技术检查。Seedance 本身没有独立文字验收接口，因此候选成片会标为 `needs_review`，不会把任务成功当作残字、译文、遮挡和切镜验收通过。真实接口兼容性以随包验证记录为准。

切换后不会把 Seedance 凭据送入混元工具会话，也不会自动切回混元。原平台配置保存到不含密钥的 `profiles.json`，密钥仍在 Windows 凭据库。

混元制作模式：插件在 Windows 11 x64 本机执行视频计算，视频理解、翻译、修改方案和画面复核由腾讯混元 API 完成。默认韩语，每批 1–20 条，一次处理一条，保留原声音轨。

普通视频处理请求使用 Hy4 的 65,536 token 输出上限，请求超时设为 1,200 秒；旧断点中的较低输出预算会升级。这个值是允许的最大输出，不要求模型每次用满。简短的工作笔记和连接探测仍使用各自的小预算。若工具参数 JSON 无效且可靠用量已达到请求预算，即使接口未标记 `length`，也会进入现有有界恢复；不执行残缺指令，不重置恢复次数。此前被错分为普通格式错误的断点可在剩余额度内恢复，重复加载不会重复扣除同一失败的恢复次数。

`style.writing_mode="vertical_ttb"` 支持单列、直立、从上向下的文字排版，默认仍为横排；保留原始译文，不支持的复杂 Unicode 序列和排版溢出会明确报错。图片证据标明取帧轮次及完整画面/裁剪范围。预览失败后，混元可以先修复当前关注区间内的已有文字段；扩展范围仍需当前预览反馈，最终验收门禁保持不变。

Codex 是任务入口：提交视频和原始要求、显示进度、转交人工审核意见并提供成片。混元模式由混元决定查看和编辑步骤、本机执行工具；Seedance 模式由 Seedance 云端理解、翻译和编辑视频，本机负责传输、持久化与技术检查，2.0 模式另外执行机械分段、流复制拼接及原声复用。插件不会在模型调用失败后切换到 Codex 或其他模型制作视频。

本版本的验收范围以随安装包提供的实际验证记录为准。模型复核通过与人工审核通过是两种状态；生成 MP4 或通过技术校验均不等于画面已获人工确认。

## 安装与配置

使用随本版本提供的 `YoungTiger-VideoLocalizer-Setup-x64.exe` 和 `.exe.sha256`，或按下文从源码构建。公开仓库中旧的 `0.1.0rc2` 安装包不包含本版混元主控流程。

1. 运行 `Get-FileHash .\YoungTiger-VideoLocalizer-Setup-x64.exe -Algorithm SHA256`，将结果与随包校验文件比对后安装。
2. 安装包自带 Python、FFmpeg、FFprobe、图像处理库和韩文字体，安装在当前 Windows 用户目录。此候选包未作发布者代码签名。
3. 在开始菜单打开 **Video Localizer 模型配置**，选择模型提供方，填写对应 API 地址和 API Key 并保存。密钥通过遮挡输入保存到 Windows 凭据管理器，配置文件保存端点和模型名。

| 字段 | 腾讯云 TokenHub 广州按量接口示例 |
| --- | --- |
| API 地址 | `https://tokenhub.tencentmaas.com/v1` |
| 模型 ID | `hy4`；也支持 `hy4-flash`，需在账号中开通对应模型 |
| API Key | 与上述端点匹配的 TokenHub 密钥 |

不同站点、套餐的接口可能不同，应使用密钥所属服务提供的地址。混元模式接受 `hy4` 和 `hy4-flash`；Seedance 默认模型为 `doubao-seedance-2-0-260128`，也保留 `doubao-seedance-2-5-260628`，默认地址为 `https://ark.cn-beijing.volces.com/api/v3`。已有配置不会因升级而自动变更，切换型号需明确保存；密钥有效不表示型号已开通。

Seedance 也支持方舟 `ep-...` 推理接入点：将接入点填入模型 ID，同时明确选择 `seedance-2.0` 或 `seedance-2.5` 系列。请求中的 `model` 原样使用接入点 ID；系列控制 15 秒分段、参考图片数量及 2.5 专用编辑参数，不会从 `ep-...` 字符串猜测实际型号。这是用户指定的能力配置，API Key 鉴权检查不等于远端接入点型号或生成权限核验。GUI 可选择系列；命令行可用 `setup --provider seedance --model ep-你的接入点 --model-family seedance-2.0 --gui`。API Key 仍保存在 Windows 凭据管理器，无需写入源码或设置永久环境变量。

Seedance 断点保存模型/接入点和系列。旧的直接模型 ID 断点仍可在相同配置下续跑；修改接入点或系列后不能混用原批次，避免把已上传或已生成的任务当成新模型结果。

```powershell
$vl = Join-Path $env:LOCALAPPDATA 'YoungTiger\VideoLocalizer\video-localizer.exe'
& $vl setup --provider seedance --gui
& $vl doctor
```

`doctor` / MCP 的 `check_setup` 只检查本机依赖和已保存的配置，不发模型请求。真实模型诊断会调用 API，需与本机检查区分；简单请求成功不能替代游戏画面、工具调用和完整视频的验证。

混元模式的真实诊断包含一次工具调用及结果回填，可额外指定一张图片；Seedance 模式的 `test-model` 只通过 GET 查询视频任务列表验证鉴权，不提交生成、不返回历史任务内容，也不验证模型开通情况，不支持 `--image`：

```powershell
& $vl test-model
& $vl test-model --image 'D:\广告素材\测试帧.png' --timeout 180
```

图片会发送至所配置的混元端点。诊断结果包含实际调用耗时和用量；返回识别文字仅表示模型已回应，不表示该文字已经人工校对。Codex 中调用 `check_model` 后使用 `batch_progress` 获取结果。

## 连接 Codex

已安装 Codex CLI 时，在 PowerShell 执行：

```powershell
& $vl connect --host codex
```

注册后重新载入插件连接，使新的进程使用当前激活版本。在 Codex 中可以让助手打开模型配置窗口、检查配置，再提交视频。无需 MCP 的助手也可以使用命令行；其他 MCP 客户端的连接参数见 `& $vl connect --help`。

## 提交 Seedance 批次

保存 Seedance 配置后，使用相同 `convert` / `convert_videos` 入口，每批 1–20 条、顺序处理。2.5 上传原视频；2.0 在本机按源帧边界机械分段，每段最多 15 秒，一条最多 30 秒的原片最多分两段，各段范围无重叠或遗漏。片段通过所配置方舟端点的 Files API（`purpose=agent`）上传，接口返回临时原文件地址后作为 `reference_video` 交给 Seedance。不会把 Files ID 伪装为素材 ID，也不借用其他上传平台。

```powershell
& $vl convert 'D:\广告素材\本批' --target 韩语 --profile source --output 'D:\广告素材\Seedance测试' --request '将原片中的文字改为韩语，保留人物、动画、镜头和原声' --max-turns 200
& $vl resume --batch-dir 'D:\广告素材\Seedance测试\batch-实际目录' --max-turns 200
```

每条原片须为 4–30 秒、24–60 fps、支持的 MP4 编码及尺寸，2.0 分段模式另要求恒定帧率。仅接受 `source` 规格。2.0 各段请求使用 `ratio=adaptive`、`duration=-1`、`generate_audio=false`，不发送 2.5 专用的 `omni_reference_task_type`。本机直接拼接云端候选视频流，复制原片音轨，不补帧、重定时、缩放或修补云端画面。原片始终只读，片段及其帧范围、哈希和云端任务 ID 分别保存。

2.0 的自动时长不保证与输入片段一致，跨段译名、字体和接缝也需要复核；原规格、总时长或音画同步不符时明确记录失败。2.5 使用整片编辑模式并生成音频，但同样不保证逐字节保留原声。两种模式都不把下载成功当作保真交付，也不在本机擦字、绘字或修补。

定稿表、术语表和参考图片可沿用对应参数；不会截断超限资料或把旧混元计划当作定稿。提示词包含残字、运动对齐、前景遮挡、切镜边界和短暂文字处理要求。没有定稿表时由 Seedance 自主翻译，保留测试版性质。

上传 ID、任务 ID、原片哈希与提示词指纹持久保存。上传使用独立的 600 秒总截止时间，普通查询与生成提交仍为 60 秒，不再让视频上传共用短请求预算。`max-turns` 在此模式表示本次等待查询次数，达到上限后可续跑同一远端任务。创建请求失败且结果不明时暂停核对，不自动重发；取消仅停止本机等待，已提交的云端任务可能继续运行与计费。原片、提供方、端点、模型或资料变化时拒绝混用原断点。

网络失败的 `last_transport_error` 会记录失败阶段、异常类别、已完整发送的请求体字节数及服务端返回的 Request ID；分段错误也会汇总到父批次。每次 socket 操作仍有 30 秒上限，因此 `network` 不表示 600 秒总时间已耗尽。写入失败时，在原截止时间内尝试读取服务端提前返回的 HTTP 响应；不会重新发送请求。已发送字节数只是完整发送块的下界，不能证明服务端是否保存文件。日志不保存密钥、临时素材地址或服务端任意错误正文；未知结果的断点仍须核对，原始网络诊断会在被阻止的续跑中保留。

官方 POST/GET 示例中的 `video_url.url` 是已可被云端读取的 HTTPS 地址或素材 ID，不是本机路径。示例不包含本机视频上传步骤。当前批次入口从本机文件上传取得引用；HTTP 生成请求格式一致不代表上传已成功或视频已生成。

下载完成后检查完整解码、尺寸、时长、帧率、原片完整性及音频保留情况；候选文件、`technical-review.json` 和审核页面保存在各视频工作目录。状态 `needs_review` 表示尚未进行独立视觉验收。只有用户明确检查整片并提交 `keep` 且技术检查全部通过时才记为人工通过；`reject` 可拒绝当前候选。需要重新编辑时创建带有明确修改要求的新批次，不自动重复收费生成。旧混元断点不能用于 Seedance。

接口依据：[创建视频任务](https://docs.volcengine.com/docs/ark/create-video-generation-task-api)、[上传文件](https://docs.volcengine.com/docs/ark/upload-files-api)、[Seedance 2.5 编辑限制](https://docs.volcengine.com/docs/ark/seedance-2-5)。

## 提交混元批次

在 Codex 中说明视频路径、输出目录和要求，例如：

> 使用 Video Localizer，把 D:\广告素材\本批 中的视频改成韩语，保留原声和原画幅，输出到 D:\广告素材\韩语成片。全部视频判断和修改决策交给 Hy4；名牌与立绘冲突的地方交给我确认。

命令行基本操作：

```powershell
& $vl convert 'D:\广告素材\本批' --target 韩语 --output 'D:\广告素材\韩语成片'
```

可以通过 `--request` 原样传入具体要求，`--max-turns` 设置每条视频本次运行最多调用模型的轮数（默认 80，允许 1–200）。达到上限会暂停并保存检查点，续跑会给本次继续处理新的轮数额度。

文件夹输入只包含该文件夹中直接存放的 MP4。每次提交 1–20 条；新批次使用独立目录，原视频保持只读。每条视频保留独立的处理状态、模型调用信息、工具执行结果和审核项。

| 可选资料 / 规格 | 参数 |
| --- | --- |
| 定稿译文 | `--translations`，UTF-8 CSV、TSV 或 JSON；CSV/TSV 首行为 `source,target` |
| 项目术语表 | `--glossary`，格式同上；Excel 可另存为 UTF-8 CSV |
| 角色参考图 | `--references`，图片目录或角色名到相对图片路径的 JSON；支持 JPEG、PNG、WebP |
| 源语言 | `--source-language`，默认自动识别 |
| 保留原片规格 | `--profile source`，默认值 |
| 2K / 120 fps | `--profile 2k120`，长边 2560、保持比例，通过重复源帧输出 120 fps |

输入范围为 MP4、每条最多 5 分钟和 512 MiB、长边不超过 1920、短边不超过 1080、最多 120 fps，一条视频流及最多一条音轨。源规格输出适用于恒定帧率；可变帧率输入使用 `2k120`。120 fps 是输出帧率，重复源帧不等于运动估计补帧；放大输出也不会恢复源片中不存在的细节。

## 混元制作与审核

混元可以查看原片和必要的连续帧，结合定稿、术语及角色参考图提出帧级编辑计划。本地工具检查计划参数后执行，实际预览返回模型；混元根据结果修订计划并重做片段。最终输出还需经过视频解码、音轨、时长及规格检查。

制作按查看、分批计划、预览和复核等阶段推进。每轮最多传回 8 张图片；Hy4 选择不超过 6 秒的当前处理区间，每次最多提交 4 个片段，生成并查看本组预览后再扩展到下一组。遇到需要人工决定的区域，可以保留审核项并继续处理其他明确区域。

需要压缩较长的对话历史时，由 Hy4 先生成工作笔记，插件保留当前编辑计划、未完成任务、人工审核及决定，并在请求中缩减旧消息；完整审计历史仍保存在磁盘。宿主助手不代写识别结论、译文或修补方案。工作笔记不能代替实际预览复核，也不能自行解决人工审核项。

工作笔记连续两次未通过格式或当前阶段的约束检查时，原笔记保持不变，插件开放三个普通工具回合，让 Hy4 补查证据、处理阻碍或请求人工审核，再重新保存有效笔记。此恢复不会绕过当前片段的预览复核或清除待审核问题。

局部分析的只读轮数上限仍然有效。若达到上限的最后一轮已经提交编辑操作，但参数校验失败，插件最多再提供两次纠错机会，由 Hy4 根据错误修正参数；宿主不代改计划，也不解除人工审核要求。只重复查看而没有提交编辑操作，不会获得此纠错额度。

常规制作请求使用 `reasoning_effort: low`、最多 65,536 输出 token 和 1,200 秒超时；输出额度包含模型推理用量。工作笔记请求仍由 Hy4 完成，使用 `thinking: disabled` 配合指定工具调用，额度为 8,192 token，超时 180 秒。

模型单次输出被截断时，每条视频最多自动恢复两次，该计数在续跑时保留。插件先压缩请求上下文并要求 Hy4 保存简短工作笔记，之后的常规请求仍使用 65,536 token 和 1,200 秒超时；第二次恢复的工作笔记额度提高到 16,384 token，超时仍为 180 秒。截断响应中的部分动作不会执行，也不会切换到其他模型。反复截断或分析长期没有推进会暂停并显示具体原因。

是否完成必须以该条视频的实际状态和成片复核范围为准。模型连通、生成预览或通过技术检查都不能据此宣称整条视频画面合格。

残字和运动修复规则保存在 `src/video_localizer/quality_rules.py`，当前版本为 `residual-motion-v6`，会进入每次制作及续跑的系统提示词。规则来自混元实际预览反馈和执行器能力核对，适用于不同视频，不包含某条视频的坐标或译文。要求混元：

- 对照同一源帧、同一区域的源图和新预览，区分漏擦笔画、字形边缘、运动错位和独立图标；依据实际证据调整遮罩。
- 分别处理进入、移动、停稳和退出阶段，检查关键帧与运动模式；保留动画期间的文字任务，不能通过缩短编辑时段掩盖错位。
- 延长文字区间前检查中间的遮挡、闪光、转场及镜头切换。前后出现同一标签不代表中间一直存在；按实际消失和重现分段，不能把译文画到原界面不存在的画面上。跟踪或遮罩报不确定时，先复查报错帧及邻帧，不能只改成固定位置或放大遮罩。
- 扩大擦除框后重查译文字号和位置；正确使用局部程序的参考帧、前景保护和透明度，避免恢复旧字或冻结背景。
- 使用真实工具执行修订，随后逐项复核残字、背景、非文字内容、运动和排版；笔记中的计划不能算作已完成修复。
- 同轮成对请求源图和当前预览，总共不超过八张图；记录实际看到的对比结论，不能把旧图占位符当作当前像素。
- 发现焦点外漏改时，先查看当前版本预览的完整首尾帧，再保存扩展后的观察范围，最后更新原有段。控制器会明确提示当前是否允许扩展；六秒范围、四段上限和预览检查仍然生效。
- 保存工作笔记时只提交有变化的任务，省略项会保留。已完成任务的证据不能用空列表覆盖；需要更新时先读取准确记录。

控制器的请求提示按混元即将接收图像的轮次计算可用操作，避免图像已经随请求发送、却仍显示上一轮“不能扩展”的情况。实际执行校验仍使用当前已完成的模型轮次，同一响应先抽图后立即改范围不会视为已经看过这些图。

`check_setup` 会返回当前进程的版本、PID、运行目录 revision 及质量规则版本/hash，以区分已安装版本和当前连接实际加载的版本。检查点与新请求用量记录也保存规则版本/hash。首次续跑旧规则任务时，保留方案、任务和人工审核，开启一次新的局部分析窗口并要求混元重新保存工作笔记；同一规则的重复续跑不重置额度，输出截断恢复次数也不会清零。提示词不能保证所有复杂画面都能修复，能力不足或多次修订仍有问题时仍须明确提交人工审核。

针对文字区域的局部修补，混元可以提交受限的 Python 语法程序，控制背景修补、前景遮挡蒙版和文字透明度。程序只能操作该区域及已查看的参考帧，使用插件提供的图像运算；不能导入模块、访问文件或网络、执行系统命令、使用循环或改变计划中锁定的译文。执行结果仍需返回混元检查。

定稿冲突、角色名牌与立绘不一致等问题需要人工决定。即使模型认为自己已认出正确角色，也不能静默改名后当作人工确认。待审核问题必须在交付前处理；审核意见返回混元继续执行。

遇到网络超时、额度不足或模型响应不符合要求，任务应明确暂停并保留已完成工作。诊断日志记录错误类别和耗时；没有得到用量的超时请求不能按零用量计算。报告中的模型复核仅反映模型对其实际查看内容的判断，未检查的帧不属于已复核范围。

复杂遮挡、极小文字、持续变形及动态背景可能需要反复修订，或最终交由人工处理。本版提供的执行能力和可用工具会传给模型；不支持的操作应报告能力限制。

## 暂停、审核与续跑

输出根目录中的每批使用独立 `batch-...` 文件夹，包含：

- `batch.json`：混元使用 schema 2，Seedance 使用 schema 3；保存批次参数、视频顺序、工作目录和精确状态，Seedance 另保存提供方、模型/接入点、系列及远端任务 ID。
- `审核.html`：可播放的成片或预览，以及尚无成片时仍需处理的审核问题。
- `videos/001/` 等：混元保存 `controller-state.json`、`executor-state.json`、`decisions.jsonl`、`review.json` 和制作素材；Seedance 保存提示词、候选视频和技术检查，2.0 另外保存 `seedance-segments` 的帧范围与哈希、`seedance-jobs` 的分段断点。

`completed` 表示混元流程完成；`needs_review` 表示需要人工决定。`paused_error`、`paused_budget`、`cancelled` 均不是完成状态。模型调用错误、轮数上限或取消会暂停整批；待审核的视频可以先保留，其余视频继续处理。当前用户在不同助手或终端中只能运行一个视频批次。

批次 JSON、CLI 和 MCP 进度保留 `phase`（当前阶段）、`read_only_turns`（连续只读分析轮数）、`compactions`（历史压缩次数）和 `output_recoveries`（截断恢复尝试次数）。这些是执行过程信息，不是完成度或画面质量分数；旧批次缺少的字段显示为空。

| 暂停信息 | 含义 |
| --- | --- |
| `status: paused_budget` | 本次模型轮数额度已用完，保存状态后暂停 |
| `status: paused_error`，`error_code: output_limit` | 模型输出被截断，有限恢复后仍无法得到完整可执行响应 |
| `status: paused_error`，`error_code: stalled` | 分析未有效推进，已暂停，避免无休止重复查看 |

应先查看对应视频的阶段、原因和已有产物，再决定是否续跑。增加 `--max-turns` 只调整本次模型请求预算；`stalled` 后直接执行 `resume` 不会重置当前局部分析额度，也不会自动消除停滞原因。

审核页在有相应依据时显示本批次内的原片截图或裁剪图、原片帧号、时间及原资料行；没有成片也可以查看这些问题。页面不链接包含完整模型对话的内部检查点。

从报告中取得实际批次路径后续跑：

```powershell
& $vl resume --batch-dir 'D:\广告素材\韩语成片\batch-实际批次名'
```

已完成的视频会跳过，其他视频从持久检查点继续。若配置中的模型或端点已经改变，应恢复原批次的配置后续跑。可给 `resume` 增加 `--max-turns` 调整本次额度。

审核决定写入 UTF-8 JSON 文件，例如 `decision.json`：

```json
{"action":"adjust_timing","start_frame":271,"end_frame":300,"note":"第271帧才切换到娜美。"}
```

将实际视频序号和问题 ID 替换到命令中：

```powershell
& $vl review --batch-dir 'D:\广告素材\韩语成片\batch-实际批次名' --video-index 1 --issue-id review-1 --decision '@D:\广告素材\decision.json'
& $vl resume --batch-dir 'D:\广告素材\韩语成片\batch-实际批次名'
```

可用动作是 `keep`、`replace`、`adjust_timing`、`retry`、`reject`；可附 `note`、`source_text`、`target_text`、`start_frame`、`end_frame`。`source_text` 用于确认精确原文，并与译文及帧区间共同绑定具体修改；帧号以原片为准，开始帧包含在内、结束帧不包含在内。决定必须来自人工，不能由宿主助手自行代选。确认某个问题不代表人工已验收整条成片。

Codex 中对应工具为 `resume_batch`、`submit_review` 和 `cancel_batch`。`cancel_batch` 请求停止当前连接中的任务；正在等待的模型请求可能在返回或超时后才响应取消。CLI 可用 Ctrl+C 停止，之后用批次目录续跑。

## 升级与回退

安装器把每个版本放入独立的 `versions` 目录，全部文件写入完成后再切换 `active.txt`。此前版本保留，已启动的进程继续使用启动时选中的版本；升级后需重新连接 MCP，才会加载新版本。

升级前保留上一版已校验的安装包。如需回退，先停止当前视频任务和插件进程，再运行上一版安装包并重新连接。安装升级保留用户配置；API Key 继续保存在 Windows 凭据管理器中。不要手动删除仍被任务使用的版本目录。

## 从源码构建

在仓库根目录可以使用已安装候选包中的依赖运行全部本机回归。以下命令设置合成视频测试需要的 FFmpeg、FFprobe 和字体，并把当前仓库源码放在导入路径前端；任意失败或跳过都会返回非零退出码。测试不需要真实 API Key，也不调用模型。

```powershell
$pluginRoot = Join-Path $env:LOCALAPPDATA 'YoungTiger\VideoLocalizer'
$revision = (Get-Content -LiteralPath (Join-Path $pluginRoot 'active.txt') -Raw).Trim()
$runtimeRoot = Join-Path $pluginRoot ('versions\' + $revision)
$env:VIDEO_LOCALIZER_TEST_FFMPEG = Join-Path $runtimeRoot 'bin\ffmpeg.exe'
$env:VIDEO_LOCALIZER_TEST_FFPROBE = Join-Path $runtimeRoot 'bin\ffprobe.exe'
$env:VIDEO_LOCALIZER_TEST_FONT = Join-Path $runtimeRoot 'fonts\NotoSansCJKkr-Regular.otf'
& (Join-Path $runtimeRoot 'runtime\python.exe') -X utf8 -c 'import sys, unittest; sys.path[:0] = ["src", "tests"]; result = unittest.TextTestRunner(verbosity=2).run(unittest.defaultTestLoader.discover("tests")); sys.exit(not result.wasSuccessful() or bool(result.skipped))'
```

在 Windows x64 上使用 Python 3.11 或更高版本运行：

```powershell
python packaging/build_windows.py --output-dir dist --cache-dir build/dependency-cache
```

构建脚本使用锁定依赖并校验 SHA-256，自动打包 `src/video_localizer` 中所有顶层 Python 模块和配置窗口脚本，随后使用包内 Python 导入全部模块并检查字体与图像库。任何导入失败都会停止构建。

已有完整缓存时可以离线构建：

```powershell
python packaging/build_windows.py --offline --output-dir dist --cache-dir build/dependency-cache
```

`--offline` 不进行网络下载。缓存缺失或校验不符会明确失败，不删除损坏缓存，也不会使用未校验的文件。不同候选版建议使用不同输出目录，保留对应安装包和校验文件。

自有代码使用条款见 `LICENSE.txt`，第三方组件按随包许可使用。源代码及安装包不包含用户视频、译文或 API Key。

相同计划版本、输出配置和窗口的重复成功渲染不再刷新分析额度；新生成文件仍须实际查看。已有待审事项阻止最终渲染时，混元应继续其他确定工作或以需要审核收尾，不能把已有候选 MP4 当作审核通过。
